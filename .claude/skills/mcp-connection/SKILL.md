# MCP connection surface

Two distinct things share this surface — keep them straight before editing:

- **Deployment-managed servers** — configured via `MCP_SERVERS`, built in
  `backend/app/agents/mcp.py`, with sidecars under `docker/mcp/`. Each must declare an
  explicit `allowed_tools` list; startup fails on a malformed or duplicated name.
- **Per-user connections** — the `mcp-user-connections` component: database rows, not
  files (`backend/app/services/mcp_connection.py`, `backend/app/agents/mcp_oauth.py`,
  the catalog in `frontend/src/lib/mcp-catalog.ts`, UI at `/api/v1/me/mcp-connections`).
  Its curated entry in `governance/manifests/curated/architectural-intent.json` carries
  the authoritative invariants — read them there, with
  `make governance-explain ID=mcp-user-connections`; do not work from memory or from
  this skill alone.

## Why this surface is different

Three standing security findings constrain it (`governance/policies/security.json` and
the component's `finding_refs`): approval-gating asymmetry (MCP-sourced tools bypass
the deferred-tool approval gate), no connection-time SSRF revalidation (URL validation
runs at write time only), and URL-embedded credentials stored unencrypted (bearer
tokens are encrypted; the URL column is not). A change here either narrows one of these
or must demonstrably not widen it — the change record says which.

## Working on it

1. Open with `gov-change` GOV-OPEN, `PATHS="backend/app/agents,backend/app/services/mcp_connection.py"`
   (add `frontend/src/lib` for catalog changes — catalog entries feed the generated
   `frontend/src/lib/mcp-logos.generated.ts`, regenerated by `bun run gen:mcp-logos`,
   never hand-edited).
2. Respect the runtime behaviors the `agents` component declares as invariants:
   unreachable servers are skipped per-turn, never fatal; tool names are prefixed per
   server so a per-user connection cannot shadow a managed server's tool; connection
   URLs are stripped of query strings and userinfo before any log or manifest.
3. Because the per-user edges live in database rows, static extraction cannot see them:
   runtime evidence comes from `governance snapshot-mcp-connections` (read-only DSN),
   never from assumptions.
4. Validate: `backend-unit`, plus `agent-evals` when tool exposure or routing changed,
   plus `preflight-mcp` when sidecar tokens are involved. Resolve IDs via
   `governance/validators.json`.
5. **Invoke `security-review` before GOV-CLOSE.** Auth, token handling, and
   user-supplied URLs reaching a connector are exactly its triggers; on this surface
   they are always present.

## Rules

- Never widen `allowed_tools` or leave it unset "temporarily" — unset means every tool
  the server advertises, ungated.
- Never log, store, or manifest a connection URL without stripping query and userinfo.
- GitHub MCP read-only is enforced at three independent layers (Compose flags, the
  settings-validator allowlist, the runtime post-probe assert); a change to one layer
  is a change to the contract all three assert together.
- A fix that touches the validation-to-connection window or the approval gate updates
  the standing finding's status in its records — silently "fixing" a tracked finding
  hides the evidence that it was ever real.
